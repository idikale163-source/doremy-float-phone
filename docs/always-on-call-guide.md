# 随时随地煲电话粥 · 常驻通话体验专项说明

> 这份文档**体验优先**：先把「煲电话粥」到底要什么效果讲清楚，再告诉你最少改哪几处、怎么验收。
> 每个文件、每个坑的完整技术细节，看配套的 `docs/call-feature-porting-guide.md`——这份是它的精简体验版。
>
> 面向对象：想让自己的副本拥有「一通电话挂着不挂、切出去也照样聊」的人（和他的 AI）。

---

## 一、什么叫「煲电话粥」

不是「能打个电话」，而是**通话像真实通话一样持续存在**。四个可验证的体验：

| 体验 | 具体表现 |
| --- | --- |
| **不中断** | 通话中返回桌面、开别的 App、切到另一个会话——通话都还在，声音不断 |
| **看得见** | 切出去时屏幕上有个浮窗，显示角色头像、名字、**跳动的通话时长** |
| **不冷场** | 你半天不说话，角色会自己找话（自动搭话），就像电话那头有人 |
| **不丢话** | 角色正说着话，你发消息——不会石沉大海，会排队等它说完自动发出 |

**缺任何一个，都不是「煲电话粥」。** 只做到前两个是「通话不中断」，只做到第三个是「会主动找话」，四个凑齐才是那个味。

---

## 二、四个支柱

| 支柱 | 解决哪个体验 | 在哪一层 | 缺了会怎样 |
| --- | --- | --- | --- |
| **A. 常驻通话层** | 不中断 | 网页 | 切会话 / 回桌面，通话被卸载，像自动挂断 |
| **B. 原生系统浮窗** | 看得见 | 原生壳 | 切出浏览器后，通话还在但**你看不见**，也不知道还通着 |
| **C. 自动搭话** | 不冷场 | 网页 + 原生心跳 | 你不说话它就干等，冷场到你想挂 |
| **D. 消息排队补发** | 不丢话 | 网页 | 角色说话时你发的消息**被静默丢弃**，你以为发出去了 |

> A + D 只动 JS，部署即生效；B + C 的后台部分要动原生壳，必须重新构建安装。

---

## 三、每根支柱的关键设计

### A. 常驻通话层（网页）

把通话状态从聊天室内部提到**全局**，让通话屏不再随聊天页卸载。

- 全局真值放 `lib/call-session-store.ts`，**只存身份**（谁在通话），不存会话对象——会话和角色按 id 现取，否则改名换头像后浮窗显示旧值。
- 由 `components/chat/call-layer.tsx` 在桌面壳里**常驻渲染**（挂在 `<MascotPreviewHost />` 之后）。
- 三个通话屏（语音 / 视频 / 群聊）对外只负责「发起」，不再自己渲染通话屏。

细节与完整文件清单见说明书 §一、§二。**最容易踩的坑**：`useSyncExternalStore` 的快照必须返回稳定引用，否则无限重渲染（说明书坑 9）。

### B. 原生系统浮窗（原生壳）

网页里的悬浮元素**永远出不了浏览器窗口**。要浮在别的 App 上层，只有原生一条路。

- `CallOverlayService.kt`：前台服务 + `WindowManager` 浮窗。
- 显隐**必须由 Activity 生命周期驱动**（`onStop` / `onStart`），不能靠网页 `visibilitychange`——App 退后台后 JS 会被系统冻结，那条链路在源头就断了（说明书坑 3）。
- **通话一通就在前台把服务暖好**，窗口先建出来藏着；切后台只改可见性——因为 Android 12+ 禁止 App 在后台启动前台服务（说明书坑 2）。
- 长按浮窗弹回复条，回复条**另开一个窗口**（不能带 `FLAG_NOT_FOCUSABLE`，否则打不了字，说明书坑 11）。

### C. 自动搭话（不冷场的关键）

「没人说话就让角色主动开口」——**做不好就是烧 token 机器**。至少要：

- **随机间隔**：在 `[min, max]` 之间取值。固定节拍像定时器，真人是忽快忽慢的。
- **条数上限**：本次通话最多 N 条（0 = 不限），防止你没在听它还在狂说。
- **空转退避**：角色这轮没说出内容，下次等待翻倍（最多 4 倍）。
- **用户一开口就清零**重算。
- **心跳搬到原生**：靠网页 `setInterval` 的话，退到后台会被节流甚至冻结，「挂着也一直聊」直接失效（说明书坑 15）。心跳放前台服务里的线程，每秒推 `tick` 事件驱动页面。
- **缩成小窗 / 切后台时的行为要明确**——这里选择了**继续**，因为用户要的就是「挂着也一直聊」。

### D. 消息排队补发（不丢话）

**根因**：通话屏的接收逻辑是 `if (状态 === IDLE) runConversationTurn(text)`——角色说话或思考时，进来的消息**被静默丢弃**；而发送键又不判断状态，看起来永远可用，于是频繁「空发」。

**修法**：
- 忙时入队，回到 `IDLE` 自动补发；
- 队列**上限 5 条**，超出拒收并**保留输入内容**（别吞掉用户打的字）；
- **一次只补发一条**：发出后状态转 `PROCESSING`，effect 重跑发现非 IDLE 自然停手——不需要额外的锁；
- 挂断清空队列；
- 让用户**看得见**：全屏顶部显示「对方说完就发 · 还有 N 条」，小窗挂「待发 N」角标。

## 四、煲电话粥专属的五个坑

> 完整 20 坑见说明书 §五。这里只挑「煲电话粥」最容易栽的五个。

1. **后台定时器被冻结** → 自动搭话停摆。心跳必须搬到原生（前台服务线程），不能靠网页 `setInterval`。
2. **时长两套时钟对不上** → 浮窗从 0 开始数，和网页显示不一致。修法：网页把已通话秒数传过去，原生记基准点按**墙钟**推算，每秒推 `tick` 回网页校准；**只前进不后退**（页面后台被冻结时报上来的值会停在旧值，无条件覆盖会把时长往回拽）。
3. **忙时丢消息** → 就是上面 D 那件事，最容易「看起来成功了其实没发」。
4. **自动搭话失控烧 token** → 见上面 C 的四条约束，一条都别省。
5. **切后台声音断** → 前台服务要声明 `foregroundServiceType="mediaPlayback"`，播放走媒体通道，才不受浮窗可见性影响。

## 五、参数速查

| 参数 | 建议值 | 作用 |
| --- | --- | --- |
| 自动搭话间隔 | `[min, max]` 随机 | 像真人，不像定时器 |
| 自动搭话条数上限 | 可配（0 = 不限） | 防止狂说 |
| 发话后等待倍率 | 每次翻倍，上限 4× | 角色无内容时退避 |
| 消息队列上限 | 5 条 | 超出保留输入、提示用户 |
| 消息补发节奏 | 一次一条 | 发后转 PROCESSING，天然节流 |
| 浮窗最大宽度 | 320dp | 头像解码降采样阈值参考（>1024 宽再降采样） |

## 六、怎么算「煲电话粥成功」

照着过一遍，全过就是成了：

- [ ] 通话中返回桌面 → 通话**还在、声音不断**
- [ ] 通话中切到微信等别的 App → **浮窗可见**，显示头像、名字、**跳动的时长**
- [ ] 浮窗可以拖动、缩放
- [ ] 轻点浮窗 → 回到小手机且通话恢复全屏
- [ ] 长按浮窗 → 回复条弹出、能打字、能发送
- [ ] 你静默一段时间 → 角色**自己开口**（挂着也一直聊）
- [ ] 角色正说话时你发消息 → 不丢，等它说完**自动补发**
- [ ] 全程通话时长**两边一致、只增不减**
- [ ] 挂断后浮窗消失，不留悬空残留
- [ ] 挂断后聊天室里那通电话**折成一条**，条数与实际对话一致
- [ ] 通话期间在聊天室发的消息**没有**被折进通话里
- [ ] 老通话（更新前打的）也能正常折叠，不显示「共0条」
- [ ] 复听角色的话放的是**当时的原音**，不是重新合成
- [ ] 通话期间**没有**收到角色的主动消息通知

## 七、动手顺序（体验优先版）

1. **先让通话不断**：全局状态 + 常驻层（支柱 A）。验证：切会话、回桌面，通话不断。
2. **再让消息不丢**：排队补发（支柱 D）。验证：角色说话时发消息会「待发 N → 自动补发」。
3. **再让它不冷场**：自动搭话（支柱 C 的网页部分，先不做原生心跳也能验证）。
4. **最后才上原生浮窗**（支柱 B + C 的原生心跳）。先做「权限 + 浮窗出现 + 拖动缩放 + 点回全屏」，再做「原生心跳 + 时长同步 + 后台语音」，最后做「长按快捷回复」。

> 前 3 步全在 JS，**部署即生效**，不用碰 Android。第 4 步才需要重新构建 APK（记得递增 `versionCode`，否则覆盖安装报「应用未安装」）。

## 八、通话之后：记录、声音、别打扰

四个支柱让通话**打得起来、挂得住**。但通话结束之后还有三件事，做不好前面全白搭——
用户会立刻感到「这通电话哪去了」。

### 8.1 聊天室里要折得起来、折得对

一通长电话留下几十条对话，聊天室里必须收成一条折叠条（「语音通话 · 全程 12:03 · 共 23 条」）。
规则错一步就是实报 bug：**聊天室消息被吞进通话**、或者**老通话折成「共 0 条」**。

三条要点（完整推导见说明书坑 21）：

1. **来源逐条判，不整段判**——`origin === "call"` 或没有 `origin`（老记录）都收，
   只有明确是聊天室等来源的才排除。整段判定会被一条新消息连坐，把几十条老对话全排除。
2. **终点手动标记优先于挂断留痕**——用户标了结尾就照标的折。挂断留痕可能是误留的
   （挂了一夜忘了挂，时长会显示成 11 小时）。
3. **起点和终点都能手动标**（右键菜单「设为通话开头 / 结尾」）——留痕被删或从未写入时的唯一救法。

### 8.2 声音要留得住（复听原音）

通话里角色每句话都是 TTS 现场合成的。**如果合成完就丢**（只放内存、挂断即失），
「复听」就只能重新合成——音色语气每次都不一样，还重复烧额度。

**做法**：合成后把音频落进媒体库，把引用写进那条消息的 `mediaData.callAudioRef`。
之后复听直接放原音。

配套两条：

- **保留策略**：默认留最近 30 天 / 400 段，超出从最旧清（音频不小，一通长电话 1～2MB）；
- **编辑 / 删除 / 重新生成时同步清掉留档**——文字改了，原音就对不上了，留着点开是另一句话。

### 8.3 通话期间别插播主动消息

**症状**：明明在通话，却按「沉默」判定生成了一条角色主动消息，**只在通知栏冒出来**，
聊天室里没有对应记录——像见鬼。

**做法**：通话开始就撤销该会话已挂的离线预约（追问兜底 / 回复兜底 / 冷场重连三类），
并且新预约挂单前先判「这个会话是不是正在通话」。两半都要做。

### 8.4 发版要真生效（PWA 缓存坑）

**症状**：修复明明上线了，用户那儿行为照旧。

**最快的诊断法**：找个代码里改过的**文案**去对。文案对不上 = 用户跑的是旧包。

**原因**：Service Worker 对静态资源用 cache-first，`CACHE_VERSION` 不升就永远不失效；
`sw.js` 自身还会被 CDN 缓存。**升版本号 + 给 sw.js 加 no-cache**，两条一起做。

## 九、一句话

> **通话状态提到常驻层，浮窗显隐交给系统生命周期，心跳搬进原生服务，
> 忙时的消息排队补发——这四件事凑齐，才是「煲电话粥」。**
>
> 挂断之后还有三件：**记录折得对（逐条判来源、手动标记优先）、声音留得住（合成即落库）、
> 通话期间不插播（撤销离线预约）。**
