## 二、按功能域归拢

### A. 通话折叠（本批改动最多、也最容易错）

**要解决的体验**：一通长电话留下几十条对话，不该在聊天室刷屏，要收成一条折叠条
（「语音通话 · 全程 12:03 · 共 23 条」）。

**为什么这块改了好几轮**——每轮都对应一个实报 bug：

| 轮次 | 问题 | 根因 |
|---|---|---|
| 1 | 折叠条根本不出现在长通话上 | 只扫当前加载的 50 条窗口，起点留痕早被挤出 → 改**全量预计算** |
| 2 | 聊天室消息被折进通话里 | 按时间区间**无差别全收** → 改只收 `origin === "call"` |
| 3 | 老通话折成「共 0 条」 | `origin` 是后加字段，**整段判定**被一条新消息连坐 → 改**逐条判定** |
| 4 | 用户标了结尾却没用 | 手动标记只当兜底，被挂断留痕盖掉 → 改**手动优先** |

**最终判定规则**（这是本批最重要的结论）：

```
起点：系统留痕「发起了语音/视频通话」
      或 用户手动标的 mediaData.callStartMarker

终点：用户手动标的 mediaData.callEndMarker   ← 优先
      否则 挂断/拒绝/取消留痕                   ← 兜底
      两者都没有 → 整段不折叠（绝不按时间猜）

成员：逐条判 —— origin === "call" 或 origin 不存在（老记录）都收；
      只有明确是其它来源（chat / custom_app / reading_discuss…）才排除

统计：条数与时长按【全量】算，不按窗口
```

**为什么「绝不按时间猜」**：曾按消息间隔推断通话何时结束，
结果把通话期间在聊天室发的消息也圈进区间、当成通话内容（实报）。

**分段补偿**：通话被聊天室消息切断时会分成多段，每段都要能看出整通的全貌——
所以每段都显示全程时长 + 总条数 + 「第 X/Y 段」；「无结束记录」**只标最后一段**。

**新增的右键菜单项**：「设为通话开头」/「设为通话结尾」——
老通话留痕丢失或从未写入时，靠这一对手工圈出区间。

### B. 通话语音留档（原音可复听）

**要解决的问题**：通话里角色的每句话都是 TTS 现场合成的；早期合成完就丢（只放内存 Map，
上限 20 段，挂断即失）。于是「通话结束后想复听当时那句」只能**重新合成**——
音色、语速、情绪每次都可能不同，还重复烧语音额度。

**做法**：合成后落进媒体库，把引用写进那条消息。

```
TTS 合成 → storeMediaBlob → media-store:// 引用
              ↓
    写进消息 mediaData.callAudioRef
```

**两条既有通道让宿主 API 零改动**（设计时的关键发现）：

1. `serializeChatMessage` **整包透传 `mediaData`** → 自定义 APP 从 `chat.readHistory` 直接读到引用；
2. 宿主代播 `voice.play` **本就支持 `media-store://` 引用**（内部 `loadMediaBlob` 转 objectURL），
   且不校验引用归属 → APP 拿到引用就能放原音，音频不过通信桥。

**新增文件**：`lib/call-audio-storage.ts`

- `persistCallAudio(blob, meta)` → 落库并返回引用
- `releaseCallAudioRef(ref)` → 丢弃留档
- 保留策略：默认 **30 天 / 400 段**，超出从最旧清（连带 `deleteMediaRef`）
- 轻量索引键：`ai_phone_call_audio_index_v1`

**善后（容易漏）**：消息被**编辑 / 删除 / 重新生成**后，留档音频与文字已经对不上，
必须同步清掉并摘掉 `callAudioRef`——否则点开听到的是另一句话。

**老记录降级**：没有留档就回退重新合成，但 UI 要**说清是原音还是重合成**。

> APP 侧怎么接这份能力，见 `docs/custom-app-call-audio.md`。

### C. 三通话屏能力对齐

| 能力 | 语音 | 视频 | 群聊 |
|---|---|---|---|
| 重听 / 编辑 / 删除 / 重新生成字幕 | 原有 | **本轮补** | 字幕操作仍未补（多发言人，`senderName` 需保留） |
| 语音落库留档 | 本轮 | 本轮 | 本轮 |
| 消息排队补发 | 原有 | **本轮补** | 原有 |
| 通话期间停推送 | 本轮 | 本轮 | 本轮 |

**顺带修的白屏**：视频屏 import 了 `useCallReplyQueue` 却从未调用，`replyQueue` 未定义，
只要渲染到引用它的分支（缩成小窗 / 挂原生浮窗）就抛 `ReferenceError` → **整个通话页白屏**。

**落库后要广播**：通话屏在聊天室之外（由 `CallLayer` 渲染），落库后必须广播
`chat-messages-updated`，否则消息要等挂断才出现在聊天室、折叠条也不更新。

### D. 通话期间停推送

**症状**：明明在通话，却按「沉默」判定生成了一条角色主动消息，**只在系统通知里冒出来**，
聊天室里没有对应记录。

**根因**：离线预约在**排期时**挂到服务端，通话开始不会自动撤销，到点照推。三类键：

| 键 | 用途 |
|---|---|
| `followup:<sessionId>:` | 追问兜底 |
| `reply:<sessionId>` | 回复兜底 |
| `idle:<ruleId>:<序号>` | 冷场重连 |

**修法（两半都要，缺一不可）**：

1. **撤销已挂的**：三通话屏 mount 时调 `suspendBailoutsForCall(sessionId)`；
2. **门控将来要挂的**：追问兜底、冷场重连在 arm 前先判 `isCallActiveForSession(sessionId)`。

**通话结束必须重挂**（这里踩过一次坑）：

撤销容易，恢复不能只靠巡检——`refreshScheduledBailouts` 每 10 分钟才跑一次，
而用户常在通话后不久就退出 App，那笔预约会一直是空的。
**症状**：打过一次电话之后，角色再也不主动搭话。

**修法**：在 `chat-call-ended` 事件里补一次重挂。该事件由 `endCall()` 派发，
且**先清 `activeCall` 再派发**，所以 arm 时的 `isCallActiveForSession` 门控会自然放行。
崩溃/强杀不派发此事件，那种情况仍由 10 分钟巡检兜底。

> 教训：**「撤销」和「恢复」是一对，写了撤销就必须想清楚谁来恢复。**
> 原先的注释写「等用户下次发消息或巡检自然重排」——前半句是错的：
> 用户发消息只重排追问排期，不会重挂冷场重连。

### E. PWA 缓存（让修复真的生效）

**症状**：修复明明上线了，用户那儿行为照旧。

**最快的诊断法**：找一处**代码里改过的文案**去对。
真实案例：折叠条代码是「共3条」、用户看到「3条消息」→ 文案不符 → 锁定旧包。

**根因 + 修法（两条一起做）**：

```js
// public/sw.js：对 /_next/static/ 用 cache-first，版本不升就永远不失效
const CACHE_VERSION = "ai-phone-pwa-v13";   // v12 → v13
```

```toml
# netlify.toml：sw.js 自身不能被 CDN 缓存
[[headers]]
  for = "/sw.js"
  [headers.values]
    Cache-Control = "no-cache, no-store, must-revalidate"
```

只升版本号不够（浏览器缓存的旧 `sw.js` 还在用旧逻辑）；
只加 no-cache 也不够（已注册的旧 SW 照样发缓存）。

## 三、开发要点（可直接复用）

1. **边界判定逐条，不要整段。** 一条新数据能让「整段判定」把几十条老数据连坐——
   实报就是老通话折成「共 0 条」。
2. **人工标记优先于自动留痕。** 用户亲手标的是明确意图，自动写的那条可能是误留的。
   当「兜底」用，就等于标了也不生效。
3. **绝不按时间断层猜边界。** 猜出来的区间一定会把无关消息卷进去。
   宁可整段不折、等用户标记。
4. **默认只加载窗口 ≠ 全量。** 任何区间统计都要基于全量记录计算，再映射回窗口。
5. **合成出来的东西要落库。** 内存缓存挂断即失，「事后想再听」就只能重算。
6. **改 `mediaData` 要自己拼全。** `updateChatMessage` 是顶层浅合并，
   传 `{newField}` 会抹掉这条消息上原有的字段（通话时长等）。
7. **删改内容时要连带清掉派生物。** 文字改了，原音就对不上了。
8. **播放 `await` 要有兜底。** 音频被别的 App 抢焦点时浏览器只发 `pause`、
   不发 `ended`，`await` 会永久挂死，状态机卡在「对方正在说话」。
   （修法：把非主动暂停也当播放结束 + 加超时闸门。）
9. **忙时分支必须显式设计。** UI 可点、后端静默丢，是最难查的一类 bug。
10. **升级 SW 要两条一起做**，且判断旧包**先对文案**。
